🏨 Project Overview & Domain Problem

Mid-Sem Status: 50% Complete

The Hotel Reservation and Billing System (HRBS) is an enterprise batch processing mainframe application developed for the subject Mainframe Technology (ID3002). The system manages large-volume hospitality bookings, verifies reservation data integrity, reconciles bookings with electronic bank payments, computes tiered Goods and Services Tax (GST), and maintains structured audit logs and database records.

⚠ The Hospitality Business Problem

  • Duplicate Bookings: Simultaneous front-desk entries cause double-booked rooms.
  • Unreconciled Payments: Guest reservations become separated from credit/UPI bank payment records.
  • Calculation Errors: Manual tax and service rate calculations create month-end accounting discrepancies.
  • Batch Scale: Hotels process thousands of check-ins and check-outs daily, demanding strict data integrity.

✅ Why Mainframe Solves It

  • High-Speed DFSORT: Rapid deduplication and sorting of fixed-block datasets.
  • Enterprise COBOL: Hardware-accelerated decimal arithmetic (`COMP-3`) with zero rounding error.
  • Transaction Integrity: Indexed VSAM (KSDS) random key updates and ACID-compliant DB2 relational tables.
  • Automated JCL Batch: Scheduled batch cycles with conditional step branching (`COND` / `IF-ELSE`).

📄 Key Program Logic: cobol/HRBSMTCH.cbl

*---- LOAD PAYMENTS INTO IN-MEMORY LOOKUP TABLE -----------------* 2000-LOAD-PAYMENTS. PERFORM 2100-READ-PAY PERFORM UNTIL END-OF-PAY ADD 1 TO WS-PAY-CNT IF WS-PAY-CNT > 100 DISPLAY 'PAYMENT TABLE OVERFLOW - INCREASE OCCURS' MOVE 16 TO RETURN-CODE STOP RUN END-IF MOVE PAY-RES-ID TO PT-KEY (WS-PAY-CNT) *> Key at cols 21-28 MOVE PAY-REC TO PT-REC (WS-PAY-CNT) *> 80-byte raw record PERFORM 2100-READ-PAY END-PERFORM. *---- SEQUENTIAL SEARCH & COMPOSITE WRITE ------------------------* 3000-MATCH-RESERVATIONS. PERFORM 3100-READ-RESV PERFORM UNTIL END-OF-RESV ADD 1 TO WS-RESV-CNT MOVE 'N' TO WS-FOUND PERFORM VARYING WS-IX FROM 1 BY 1 UNTIL WS-IX > WS-PAY-CNT OR FOUND-MATCH IF PT-KEY (WS-IX) = RV-ID *> Check reservation key SET FOUND-MATCH TO TRUE MOVE RESV-REC TO OUT-RESV *> First 80 bytes MOVE PT-REC (WS-IX) TO OUT-PAY *> Second 80 bytes WRITE OUT-REC *> Output 160 bytes ADD 1 TO WS-MATCH-CNT END-IF END-PERFORM IF NOT FOUND-MATCH ADD 1 TO WS-NOMATCH-CNT END-IF PERFORM 3100-READ-RESV END-PERFORM.
Plain-English Summary for Viva: Rather than forcing both files to be sorted in identical key order before execution, the COBOL program loads all 50 payment receipts into a 100-entry internal table. It then streams the reservations sequentially and performs table lookups. This achieves $O(M imes N)$ execution in milliseconds while avoiding external sort passes.

COBOL Validation Engine (HRBSVAL)

PLANNED

Filters sorted reservations against 10 integrity rules (dates, room rates, calendar bounds). Writes 80-byte valid records and 120-byte reject records (RESERV.REJECT).

Expected: 90 clean records valid | 15 test errors routed to reject log
  1. Record type must strictly equal 'RSV'.
  2. Reservation ID must be 'RS' + 6 numeric digits.
  3. Booking date must be valid YYMMDD.
  4. Check-in date must be valid YYYYMMDD with leap year check.
  5. Check-out date must be valid YYYYMMDD.
  6. Check-out date must be strictly after Check-in date.
  7. Room category must be 'STD ', 'DLX ', or 'STE '.
  8. Guest count must be between 1 and 4 occupants.
  9. Room rate must match tariff (STD=3500, DLX=5200, STE=8800).
  10. Status must be Confirmed ('C'), Cancelled ('X'), or Out ('O').
